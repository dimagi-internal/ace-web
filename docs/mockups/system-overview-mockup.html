Judge Rubric
Executability: Can a non-expert FLW follow the visit structure?
Verifiability: Can each delivery be verified with the Evidence Model?
Measurability: Are success metrics defined and collectible?
Stage-gate clarity: Are go/no-go criteria explicit?
Resource realism: Are time, budget, and FLW counts feasible?
Process (from SKILL.md)
  1. Receive the raw idea from the user or a prior cycle's learnings-summary.
  2. Determine archetype: atomic-visit, focus-group, or multi-stage.
  3. Draft the IDD using the appropriate template from templates/idd-*.md.
  4. Iterate with the user in review mode (auto-approve in auto mode).
  5. Self-evaluate with the stress-test rubric (5 questions above).
  6. Write the final IDD to idd.md and update state.yaml.

app-builder

Orchestrates the app building phase of CRISPR-Connect: idea iteration into an IDD, passing the IDD to Nova for Learn and Deliver apps, deploying to CCHQ, testing, and creating training materials.

Execution Pattern

Sequential with Parallel Windows

The app-builder runs skills mostly in sequence, with two parallel windows where independent skills execute concurrently:

  1. idea-to-idd — sequential (gate)
  2. idd-to-learn-app + idd-to-deliver-app — parallel
  3. app-deploy — sequential (gate)
  4. app-test + training-materials — parallel

In review mode, gates pause for human approval. In auto mode, gates auto-approve after judge passes.
