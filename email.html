The chat tells you what it's doing.

Three quiet but constant chat-UI gaps closed in one ship: titles flow live, stopped turns explain themselves, and broken URLs land somewhere real instead of an infinite spinner.

Live auto-titles in the chat header and sidebar

Server-generated chat titles now appear the moment they're ready, instead of staying Untitled until you reload the tab. The auto-title task already existed — we just never broadcast the result. Now it pushes a session.title_updated WebSocket event that both the chat header and the recent-sessions sidebar pick up automatically.

After: header and sidebar both flip to the auto-derived title within ~30s of the first response, no refresh.

Stopped and errored messages now say so

Pressing stop used to leave an empty grey pill — you couldn't tell whether anything happened. The backend was already labelling those messages as cancelled with the partial-character count; the frontend just didn't render it. Now the bubble shows a clear Stopped indicator (and an amber warning row when the CLI itself errored), with any partial text preserved above.

After: stop pressed before tokens arrived → a clean Stopped indicator. Stop after streaming starts also shows the partial text it captured.

Try it on labs →

Bad chat URLs land on a real page

A deleted-or-invalid chat slug used to hang on Loading… forever — the page caught the 404 with a state collision that never escaped the loading branch. Now you get a recovery page with two affordances: start a new chat or jump to all chats.

After: explicit recovery page with two recovery affordances.
